# RepoArena UI Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the premium, responsive Phase 1 RepoArena UI that accepts two repository URLs and renders a typed comparison result supplied by Gökcan's API layer.

**Architecture:** Next.js App Router will own the page shells and metadata. Small client components will own form and loading interaction; presentational landing and comparison components consume typed props only, so the API implementation can arrive independently. A local, clearly labelled preview fixture allows the UI route to be visually verified before the real endpoint lands.

**Tech Stack:** Next.js, React, TypeScript, Tailwind CSS, Lucide React, Vitest and Testing Library.

## Global Constraints

- Dark-first only for Phase 1; charcoal surfaces, warm orange action/score accent, and no generic gradient hero.
- Use visible form labels, keyboard focus, semantic controls, reduced motion, and a 44px minimum interactive target.
- Repository names, technical measures, and scores use a monospace face; prose uses the application body face.
- UI code must consume `ComparisonResult` from `src/types/comparison.ts`, never raw GitHub API payloads.
- Gökcan exclusively owns `src/lib/github/**`, `src/lib/scoring/**`, `src/app/api/compare/route.ts`, and the shared type contract.
- Do not add OAuth, Supabase, persistence, charts, or any Phase 2 capability.
